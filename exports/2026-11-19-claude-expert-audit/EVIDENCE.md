### 怎样审计一轮
1. 使用 runs 下的 ROUND.md 定位，按父候选 ID 找真正的父版；仓库的相邻轮次可能属于不同分支。
2. generation.json 含当前提交之前模型实际收发及复核事件，关联分两种。日志保存了 model_calls 时可通过 call_id 核对；旧版本只有顺序，包里给出提交前的事件窗口，并保留完整 events.jsonl。对续跑中断、没有 submitted 事件或缺末次回执的记录，去看 usage、官方 receipt、以及升级前的副本，勿自行补写输入或解释。运行结束后的未提交交互仅在运行级事件流中。
3. 文本证据依次为原始请求、模型对外输出、候选 docstring 和运行日志。私下推理不属于可读取证据。缺请求的模板不能被标为当时已发送。34.75 原版十轮有 22 条模型计量，模型请求和回复正文明细为零；后来的 22120 有 23 对实际请求与回复。计量次数与生成候选数口径不同。
4. receipt.json 记录已提交时的完整物理回执、账本状态、已捕获的子项及日志摘要。亲历的成功九组训练与公开六组、开发三组分列。accepted 或 failed 行无完整候选分，即使已有部分物理数据。真实 −100 分在表中保留。跨机的绝对分值受环境影响，论文、运行注释和审计归因与物理实测分开。
5. before-upgrade 保存有单独副本的两个工作区，historical-index 保留原始早期归档视图，两者不都代表新提交。收到新一轮回执后分数会变；每个运行的采集时间见 run.json。采集依次读取账本、事件流、文件，正在运行时可能会相差一条事件。遇到差异优先查实际候选 ID、账本与完整矩阵。

### 规则与交付范围
规则及本地任务包接口说明在 rules，官方题目见[赛题二](https://www.aicomp.cn/tracks/tracks-4/5590.html)，答疑见[官方问题表](https://www.kdocs.cn/l/ctC3X4gohXAt)。正式训练可复用本次自己的证据，验证集结果只用于候选确定后的检查。包内含队伍复核所需文本、各轮源码和原图；SSH 登录材料、模型 API 密钥、原始预算数据库及大型版图未打包。模型可见日志筛掉身份认证字段。审计包留在本地，由队伍决定何时交给 Claude。
