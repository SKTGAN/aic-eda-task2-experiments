# Claude 审计与实现任务
你接手的是中国高校 EDA 赛题二。队伍的 Harness 调用竞赛指定模型，从官方初始 GNN 切分程序出发，自动生成损失或解码候选，并由官方外层执行物理评估。正式单次运行最多十次提交、模型费用最多十五元。训练九组为三算例各三种子；同次完整训练总分用于候选选择。

**首要交付：以 34.75 版本的搜索框架为基础，审查并修订它给模型的专业知识，产出可运行的 K1 Harness。** 请你自己检查 34.75 的证据；允许与本包分析意见不同。其他研究方向记录为下一阶段，以便区分收益来源。

1. 先核对 `runs/15332-claude-original-34` 的 R2、R3、R4、R6。以本次不同的父版与逐种子数据说明原版为什么可能成功、哪里退步。区分确证事实、候选解释和待验证的因果假设。对照 22120 十轮和 10820 分支十轮。对 30924 先区分运行失败和算法降分。逐轮查回执和模型真正收到的内容，有缺口则标明。允许只引用可审计的公开理由。
2. 审计 `edit-this/` 中初始提示、后续系统提示、开局替代方案和复核模板、代码内嵌指导，逐条提交“来源 / 原句位置 / 是否离线经验 / 如何处理”。说明原版关于损失量级、面积分界、二维与三维时序的引导分别出现在哪，何者值得保留。不要把离线调出来的算例、种子、公式、倍率、补丁或历史赢家带入正式 Agent。
3. 在干净副本中实现 K1。采用用户的“专业知识优先”顺序，本次只改专家内容及保证其正确投放所必需的路径。尽可能保持选父、生成/复核调用次数策略和评估接口一致。原始程序按官方起点，使用允许的首次自然语言知识，在 200 计数单位内。检查首次、重试、续跑、第二轮和开局复核从各入口实际送出的内容。若旧版在普通提示中重复离线知识，要披露修正带来的差异。无需加入新物理评估通道。自测、双角色、保优父版本和跨机并行只做后续单独方案，避免混杂实验。
4. 返回一个完整可放入官方工程的 `AgenticBench/agent/loss_decoder/` 目录，一个相对 `edit-this/` 的统一 diff，一份中文审计说明、一份逐项改动与预期及可推翻条件、一份可执行的本地测试与真实测试输出。验证官方函数初值一致、Agent 导入、知识计数（标题加正文）、首次发送/续跑去重及官方提交路径。README 写出复测命令与依赖；若受环境限制，请准确说明已测项目。请区分本地测试、历史数据回放和新正式物理成绩。
5. 提供后续 K0 对 K1 同硬件、同模型、同官方起点和同预算的对照方案。最好交叉交换机器并重复独立运行，记录完整矩阵最佳分、首次超过本机起点的评估次数、重复矩阵数、目标例和另两例的变化、费用和总时长。不能由单次训练冠军宣称因果关系。
