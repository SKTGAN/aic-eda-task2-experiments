## 运行时改动

1. 前两轮各从官方起点改一个组件。之后每轮传入一个明确的父候选，只允许改其损失函数或解码器其中之一。挑选下一轮父候选和最终按官方完整成绩选优分开。
2. 若冠军的子候选复现了九组有效计分和原始时序，或连续两个实测子候选没有超越冠军，优先选未作为替代分支探索过、成绩较高且有不同实测时序的父候选。九组时序相同不等于实例分层相同。
3. 子候选总分虽退步，但超过三分之一的种子改善、覆盖至少两个算例，且大部分损失集中在一个种子时，可试一次定向修补。修补预算每次运行最多两次；模型同时收到要保护和要修复的实测记录。该阈值是开发启发式，并非比赛规则或选择最终候选的评分公式。
4. 每个提案可看到所选父本此前在同一组件上的试验、配对分差、各组收益和损失对总分的贡献，以及与历史候选的时序重复证据。已生成的程序继续通过官方静态校验器。没有额外的候选评估接口。
5. 官方回执确认成绩后先保存最优候选，再解析附加物理报告。附加报告不兼容时记录 `feedback_degraded`，保留官方基础反馈继续运行。历史分层比较覆盖 Python 3.8 以及整体翻层。

## 如何复核

在 `aic-eda-task2` 根目录执行：

```powershell
python -B -m unittest discover -s harness-branching/tests -v
python -B harness-branching/tools/replay_runs.py --output exports/2026-11-18-overnight/branching-three-machine-replay.json
```

回放的每一行只使用当时已发生的真实训练回执，预测的是下一轮选父和改动组件。后续实际分数属于旧版提交的候选，不能当作新版得分。测试和回放可在 Python 3.8.20 运行。正式效果要在同一环境从官方起点独立运行一轮完整预算后比较。

建议验收：先核对实际第 3 个候选父本和改动组件，再比较相同十次评估下的九组最高分、完整时序重复次数、以及预先选定冠军的六组公开验证分。公开验证仅在训练选定代码后运行。
